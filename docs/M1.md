# M1 design note: Interop read-only (SFTP over the FUSE front end)

Status: **design approved, in progress.** This is the working plan for milestone M1
(PROPOSAL.md section 18). Update it as decisions land.

## First live mount (2026-07-17) findings

The package installed and the helper mounted a real remote SFTP host: the volume mounted at
`/boot/home/mnt/sftp` (confirmed `userlandfs` via `stat -f`) and served the real remote home
(distinct from the local one). So the connect -> mount -> browse path works end to end.

Two runtime problems surfaced, both now understood:

1. **The add-on process died after the connection went idle, leaving a zombie mount** (mounted
   per the kernel, but the backing `userlandfs_server campiello_sftp` gone, so the folder shows
   empty and reads return errors). No crash in syslog -> signal termination. Cause: when the
   SSH connection drops, libssh2 writes to a broken socket and the default **SIGPIPE** kills
   the process. **Fixed:** `SftpBackend::Connect` now `signal(SIGPIPE, SIG_IGN)`, so a dropped
   connection surfaces as an I/O error instead of killing the process.
2. **No Desktop disk icon.** The mount was reachable at `/boot/home/mnt/sftp` but did not show
   as a volume on the Desktop. Cause: Tracker gives a Desktop disk icon to top-level volumes
   (`/boot`, `/Magazzino`) but not to mounts nested inside another volume (`/boot/system`,
   `/boot/home/config` show no Desktop icon either). **Fixed:** the helper now mounts at a
   top-level path `/<name>` (the disk name, defaulting to the host; `mkdir` at `/` is allowed),
   so it appears on the Desktop like the other disks. Pending live confirmation that a
   device-less userlandfs volume at top level does get the icon.

**Reconnect on a dropped session (done).** `SftpBackend` now keeps its config + known-hosts
path, and Stat/ReadDir/Open detect a dead socket (`libssh2_session_last_errno` in the
SOCKET_SEND/RECV/DISCONNECT/TIMEOUT set) and transparently reconnect once and retry, re-verifying
the already-pinned host key (a changed key aborts the reconnect). So after a long idle the first
browse re-establishes the session instead of failing. Open file handles do not survive a
reconnect (a mid-read across a drop still errors, and FUSE reopens) - acceptable for M1; a
handle-virtualizing reconnect is a later refinement. Read/Close are not wrapped (they act on a
handle from an already-live session).

Remaining runtime confirmation (needs a live mount): the Desktop-icon appearance for a
device-less top-level userlandfs volume, and the error-return sign convention.

## Goal
A remote SFTP host appears as a folder in Tracker; you browse and read files. The first
visible "World-O'-Networking" moment. M1 may still require entering a host once; discovery and
pairing (which remove that step) arrive in M2.

## Architecture

```
Tracker
  |
userlandfs  (FUSE bridge, libuserlandfs_fuse.so, fuse_main)   <- verified M0
  |
Fondamenta FUSE front end  (struct fuse_operations)           <- NEW  (src/fondamenta/fuse/)
  |
PeerBackend  (internal abstraction)                            <- DONE
  |
SftpBackend  (libssh2)                                         <- NEW  (src/fondamenta/backend/)
  |
remote SFTP server  (an OpenSSH host, a NAS, a Linux box...)
```

The FUSE front end drives a `PeerBackend`, so it also hosts `CnpBackend` (read-only browse) for
free. The FUSE bridge's unmount was clean in M0 (VERIFIED.md section 1), unlike the native
`fs_interface` (which KDL'd), so M1 is the mountable, demonstrable path that sidesteps the
unmount hazard.

## Component 1 - Fondamenta FUSE front end (`src/fondamenta/fuse/`)

A userlandfs FUSE add-on: `#define FUSE_USE_VERSION 26`, built against
`headers/private/userlandfs/fuse/fuse.h`, links `libuserlandfs_fuse.so`, uses the `fuse_main`
model (all verified M0). Implements the read subset of `struct fuse_operations`:

| op | maps to |
| --- | --- |
| `init` / `destroy` | build / tear down the backend (open/close the SFTP session) |
| `getattr` | `PeerBackend::Stat` -> fill `struct stat` |
| `readdir` | `PeerBackend::ReadDir` -> `filler()` each entry |
| `open` | reject `O_WRONLY`/`O_RDWR` with `-EROFS` (read-only M1); else `PeerBackend::Open`, stash handle in `fi->fh` |
| `read` | `PeerBackend::Read(handle, offset, size)` |
| `release` | `PeerBackend::Close(handle)` |
| `statfs` | minimal; report a large read-only volume |
| `readlink` | optional, deferred |

- Translation layer (unit-testable off Haiku): `wire::Stat` -> `struct stat`
  (`st_mode`, `st_size`, `st_mtim`, `st_crtim`, `st_ino`), and `BackendStatus` -> `-errno`
  (`kNotFound`->`-ENOENT`, `kAccessDenied`->`-EACCES`, `kNotADirectory`->`-ENOTDIR`,
  `kIsADirectory`->`-EISDIR`, `kUnsupported`->`-ENOSYS`, else `-EIO`).
- Threading: FUSE is multithreaded by default but a single SFTP session is not thread-safe.
  M1 decision: one `std::mutex` in the front-end wrapper around each `PeerBackend` call; revisit
  with a connection pool if it becomes a bottleneck.
- Mount: `fs_mount_volume(where, NULL, "userlandfs", B_MOUNT_READ_ONLY, "campiello_sftp <opts>")`
  - the first whitespace token of `parameters` is the userland-fs name; the remainder reaches
  the add-on. Re-verify the exact forwarding against the installed userlandfs at build
  (VERIFIED.md section 2).

## Component 2 - `SftpBackend` (`src/fondamenta/backend/`)

Implements the `PeerBackend` read subset with libssh2; the write methods inherit the
`kUnsupported` default (M1 is read-only).

- Session: TCP connect -> `libssh2_session_init` -> `libssh2_session_handshake` -> host-key TOFU
  (`SftpKnownHosts`: pin the host key on first sight, re-prompt on change, mirroring the CNP
  trust model) -> auth (`libssh2_userauth_publickey*` or `_password`) -> `libssh2_sftp_init`.
- Ops: `Stat`->`libssh2_sftp_stat`; `ReadDir`->`libssh2_sftp_opendir`+`readdir_ex`;
  `Open`->`libssh2_sftp_open` (store `LIBSSH2_SFTP_HANDLE*` by our `uint64`);
  `Read`->`libssh2_sftp_seek64`+`read`; `Close`->`libssh2_sftp_close`. `attrs` stays empty
  (SFTP has no BFS attributes).
- The libssh2 API signatures MUST be verified against the installed `libssh2_devel` headers
  before coding (working-agreement rule 1). Needs `pkgman install libssh2_devel`.

## Component 3 - mount helper [done]

`campiello_mount` (`src/fondamenta/mount/campiello_mount.cpp`): a libbe GUI that collects host
/ user / auth, validates the login via an `SftpBackend` connect (pinning the host key on first
use with a one-tap BAlert), then mounts read-only with `fs_mount_volume(..., "userlandfs",
B_MOUNT_READ_ONLY, BuildMountParameters(config))` and opens the folder in Tracker. Credentials
are typed each time, not written to a config file (experience rule). End-user strings Italian.
Links clean against libbe; the live GUI/mount is a manual test. Full mount-management UI (a
list of mounts, one-click unmount) is still M5.

## Manual mount demo (real Haiku, after commit 4)
Build the add-on, install it where userlandfs looks, and mount, e.g.:

    cd tests/fuse && make addon
    mkdir -p ~/config/non-packaged/add-ons/userlandfs
    cp campiello_sftp ~/config/non-packaged/add-ons/userlandfs/
    mkdir -p /tmp/win
    CAMPIELLO_SFTP_HOST=<ip> CAMPIELLO_SFTP_USER=<user> CAMPIELLO_SFTP_PASS=<pass> \
        mount -t userlandfs -o ro -p "campiello_sftp" /tmp/win

Then browse /tmp/win in Tracker. Unmount was clean for the FUSE bridge in M0, but save work
first. Confirm the error-return sign open item (a missing file should read as "not found").

## To verify before/while coding
- libssh2 exact signatures -> against `libssh2_devel`.
- userlandfs `parameters` -> add-on argv forwarding -> against installed userlandfs.
- `fuse_operations` field offsets at `FUSE_USE_VERSION 26` -> verified against installed
  `fuse.h`; `CampielloFuse.cpp` compiles clean against it (`tests/fuse/` fuse-build).
- **Error-return sign convention (open, needs the mount test):** on Haiku the POSIX errno
  macros are themselves negative Haiku status codes (`ENOENT == -2147459069`), so the libfuse
  `-errno` convention yields a positive value. `FuseTranslate::ErrnoFor` follows the same
  `-errno` form as the M0 passthrough (`campiello_passthrough.c`), but the passthrough's error
  paths were never runtime-exercised, so whether the userlandfs FUSE bridge wants `-errno`
  (positive on Haiku) or the raw negative status is unconfirmed. Confirm at the first mount by
  checking that a missing path reports "file not found" and not a spurious error. If wrong, the
  fix is localized to `ErrnoFor`.

## Licensing note (FUSE header)
The userlandfs `fuse.h` header is LGPL-licensed text (it is the libfuse API description), but
the linked implementation is Haiku's `libuserlandfs_fuse.so` (Haiku/MIT), not GNU libfuse. No
LGPL/GPL library is linked into the core; this matches the M0 FUSE-front-end decision already
in the tree (`src/fondamenta/smoke/`).
